# 需求文档

## 简介

用户认证系统为北美生活决策顾问平台提供用户注册、登录、会话管理和账户安全功能。系统支持邮箱密码登录和第三方 OAuth 登录，确保用户数据安全和良好的登录体验。

## 术语表

- **用户（User）**: 使用系统的个人，拥有唯一账户
- **认证（Authentication）**: 验证用户身份的过程
- **会话（Session）**: 用户登录后的有效期状态
- **访问令牌（Access_Token）**: 用于 API 请求认证的短期令牌
- **刷新令牌（Refresh_Token）**: 用于获取新访问令牌的长期令牌
- **OAuth_Provider**: 第三方登录服务提供商（Google、GitHub）
- **密码哈希（Password_Hash）**: 密码的单向加密存储形式

## 需求

### 需求 1: 邮箱注册

**用户故事:** 作为新用户，我想要使用邮箱注册账户，以便开始使用系统功能

#### 验收标准

1. WHEN 用户提交注册表单 THEN 系统应当验证邮箱格式的有效性
2. WHEN 邮箱已被注册 THEN 系统应当返回错误提示而不泄露具体用户信息
3. WHEN 密码不符合强度要求 THEN 系统应当显示具体的密码规则提示
4. THE 密码强度规则应当要求：最少 8 位，包含大小写字母和数字
5. WHEN 注册成功 THEN 系统应当使用 bcrypt 哈希存储密码
6. WHEN 注册成功 THEN 系统应当发送验证邮件到用户邮箱
7. WHEN 用户点击验证链接 THEN 系统应当激活账户并允许登录

### 需求 2: 邮箱密码登录

**用户故事:** 作为已注册用户，我想要使用邮箱密码登录，以便访问我的账户

#### 验收标准

1. WHEN 用户提交登录表单 THEN 系统应当验证邮箱和密码的匹配性
2. WHEN 登录凭证错误 THEN 系统应当返回通用错误信息而不区分邮箱或密码错误
3. WHEN 账户未验证 THEN 系统应当提示用户验证邮箱并提供重发验证邮件选项
4. WHEN 登录成功 THEN 系统应当生成 Access_Token 和 Refresh_Token
5. THE Access_Token 有效期应当为 15 分钟
6. THE Refresh_Token 有效期应当为 7 天
7. WHEN 登录成功 THEN 系统应当记录登录时间和 IP 地址

### 需求 3: OAuth 第三方登录

**用户故事:** 作为用户，我想要使用 Google 或 GitHub 账号快速登录，以便省去注册流程

#### 验收标准

1. THE 系统应当支持 Google OAuth 2.0 登录
2. THE 系统应当支持 GitHub OAuth 登录
3. WHEN 用户首次使用 OAuth 登录 THEN 系统应当自动创建关联账户
4. WHEN OAuth 账户邮箱已存在 THEN 系统应当关联到现有账户
5. WHEN OAuth 登录成功 THEN 系统应当生成与邮箱登录相同的令牌
6. WHEN OAuth 提供商返回错误 THEN 系统应当显示友好的错误提示

### 需求 4: 令牌刷新

**用户故事:** 作为已登录用户，我想要会话自动续期，以便不需要频繁重新登录

#### 验收标准

1. WHEN Access_Token 过期 THEN 前端应当自动使用 Refresh_Token 获取新令牌
2. WHEN Refresh_Token 有效 THEN 系统应当返回新的 Access_Token 和 Refresh_Token
3. WHEN Refresh_Token 过期或无效 THEN 系统应当要求用户重新登录
4. THE 令牌刷新应当实现令牌轮换以防止重放攻击
5. WHEN 检测到 Refresh_Token 被重复使用 THEN 系统应当使该用户所有令牌失效

### 需求 5: 登出

**用户故事:** 作为已登录用户，我想要安全登出，以便保护我的账户安全

#### 验收标准

1. WHEN 用户点击登出 THEN 系统应当使当前 Refresh_Token 失效
2. WHEN 用户选择"登出所有设备" THEN 系统应当使该用户所有 Refresh_Token 失效
3. WHEN 登出成功 THEN 前端应当清除本地存储的所有令牌
4. WHEN 登出成功 THEN 系统应当将用户重定向到首页

### 需求 6: 密码重置

**用户故事:** 作为忘记密码的用户，我想要重置密码，以便重新获得账户访问权限

#### 验收标准

1. WHEN 用户请求密码重置 THEN 系统应当发送重置链接到注册邮箱
2. THE 密码重置链接有效期应当为 1 小时
3. WHEN 重置链接被使用 THEN 系统应当使该链接立即失效
4. WHEN 用户设置新密码 THEN 系统应当验证密码强度
5. WHEN 密码重置成功 THEN 系统应当使该用户所有现有会话失效
6. IF 邮箱不存在 THEN 系统应当返回相同的成功提示以防止邮箱枚举

### 需求 7: 账户安全

**用户故事:** 作为用户，我想要我的账户受到保护，以便防止未授权访问

#### 验收标准

1. WHEN 同一 IP 连续 5 次登录失败 THEN 系统应当对该 IP 实施 15 分钟锁定
2. WHEN 同一账户连续 10 次登录失败 THEN 系统应当锁定账户并发送通知邮件
3. THE 系统应当在所有认证端点实施速率限制
4. WHEN 检测到异常登录位置 THEN 系统应当发送安全提醒邮件
5. THE 所有密码传输应当通过 HTTPS 加密

### 需求 8: 用户资料管理

**用户故事:** 作为已登录用户，我想要管理我的基本资料，以便个性化我的账户

#### 验收标准

1. WHEN 用户访问个人资料页 THEN 系统应当显示当前用户信息
2. THE 用户应当能够修改：显示名称、头像、语言偏好
3. WHEN 用户修改邮箱 THEN 系统应当发送验证邮件到新邮箱
4. WHEN 新邮箱验证成功 THEN 系统应当更新账户邮箱
5. WHEN 用户修改密码 THEN 系统应当验证当前密码

### 需求 9: 账户删除

**用户故事:** 作为用户，我想要能够删除我的账户，以便行使数据删除权利

#### 验收标准

1. WHEN 用户请求删除账户 THEN 系统应当要求输入密码确认
2. WHEN 确认删除 THEN 系统应当发送确认邮件
3. THE 账户删除应当有 7 天冷静期，期间可撤销
4. WHEN 冷静期结束 THEN 系统应当永久删除用户所有个人数据
5. THE 删除操作应当符合 GDPR 和 CCPA 数据删除要求
